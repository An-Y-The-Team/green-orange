# [Intermediate] Implement Quotes / Báo giá (with line items)

> **Labels:** `area:backend` · `crud` · `domain:greenorange` · `difficulty:hard`
> **Depends on:** #07
> **Good for:** 1 student — introduces **nested data**.

## Background

**Báo giá (Quote)** is the priced offer sent to a client; a **Quyết toán** is the
same shape reconciling actual costs (the `type` field discriminates them). This is
the v1 shape of that resource, and it is what you build here. crm-web does call
`GET /quotes`, `GET /quotes/{id}`, `POST /quotes` (see
[`quotes/queries.ts`](<../../apps/crm-web/src/app/(dashboard)/quotes/queries.ts>) and
[`create-quote.ts`](<../../apps/crm-web/src/app/(dashboard)/quotes/actions/create-quote.ts>)),
but against the **v2** field shapes — read those files for flavour, not as your
contract.

**New concept:** a quote has a **list of line items** (`items: QuoteItem[]`). This is
the first resource that isn't a flat row. You have two valid approaches — pick one
and note why in the PR:

- **(A) JSON column (simplest, recommended for teaching):** store `items` as a
  JSON/JSONB column. In SQLModel: `items: list[QuoteItem] = Field(sa_column=Column(JSON))`
  with `QuoteItem` as a plain Pydantic/SQLModel (non-table) model. The whole quote
  round-trips as one document.
- **(B) Child table + relationship (more "correct", harder):** a `QuoteItem` table
  with a FK to `quote.id` and a SQLModel `Relationship`. Teaches one-to-many but
  needs nested create handling.

The field tables below **are** the contract for this task. (They used to be checked
against `Quote` + `QuoteItem` types in crm-web; that file is gone — see
[00 — Choose your backend](00-choose-your-backend.md).)

## Fields

### Quote

| Field          | Type        | Notes                                                              |
| -------------- | ----------- | ------------------------------------------------------------------ |
| `id`           | int         | server-assigned                                                    |
| `code`         | str         | e.g. `BG-001` — index it                                           |
| `project_code` | str         | the project this quotes — index it                                 |
| `customer`     | str         |                                                                    |
| `title`        | str         |                                                                    |
| `type`         | str         | `"bao_gia" \| "quyet_toan"`                                        |
| `issue_date`   | date        |                                                                    |
| `valid_until`  | date        |                                                                    |
| `status`       | str         | `"nhap" \| "da_gui" \| "da_duyet" \| "tu_choi"` (default `"nhap"`) |
| `items`        | QuoteItem[] | nested — see approach A/B above                                    |
| `vat_rate`     | float       | e.g. `0.08` for 8%                                                 |
| `notes`        | str         |                                                                    |

### QuoteItem (nested)

| Field         | Type |
| ------------- | ---- |
| `description` | str  |
| `unit`        | str  |
| `quantity`    | int  |
| `unit_price`  | int  |

## Task

1. Model `app/models/quote.py` with your chosen items approach; index `code` and
   `project_code`.
2. Register in [`app/models/__init__.py`](../../apps/crm-api/app/models/__init__.py).
3. Routes `app/api/routes/quotes.py` — full CRUD (`list`, `get`, `create`,
   `update`, `delete`), `CurrentUser`-protected. Ensure `create` and `get` round-trip
   the nested `items`.
4. Register the router in [`app/main.py`](../../apps/crm-api/app/main.py).
5. Migration: `uv run alembic revision --autogenerate -m "quotes"` → `upgrade head`.
   _(If you use a JSON column, double-check the autogenerated migration — Alembic
   sometimes needs a hand with JSON types.)_
6. Test `tests/test_quotes.py` — **include a case that creates a quote with ≥2 items
   and asserts they come back intact** (order + values).

## Acceptance criteria

- [ ] Full CRUD on `/quotes` works in `/docs`, **including nested `items`** on create
      and read.
- [ ] `QuotePublic` matches the Quote table above 1:1 (`vat_rate` as a float; `items`
      as an array of `{description, unit, quantity, unit_price}`).
- [ ] Router registered; migration + test (with the multi-item case) committed and
      passing.
- [ ] A `curl` round-trip creates a two-item quote and reads both items back.

## Hints & references

- Approach A JSON column needs `from sqlalchemy import Column, JSON` and
  `from sqlmodel import Field`.
- A `quyết toán` is just a quote with `type="quyet_toan"` — no separate model.
- Don't compute totals server-side — match the field table; totals are derived from
  `items` + `vat_rate` by whoever renders the document.

## Definition of done

`/quotes` round-trips a quote with its line items in `/docs`, with a multi-item test.
